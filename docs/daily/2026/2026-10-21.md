## 3. Các lỗi và thay đổi đáng chú ý

### PSCI/CPU1 và MPIDR

- P1E/P1F có symbol/callback trong ELF nhưng chưa thực thi quy trình bật CPU1. Không dùng symbol presence để đánh dấu hardware PASS.
- P1H loại callback không hoàn chỉnh và giữ CPU_ON disabled. P1I bỏ ánh xạ CPU0 alias trong core-position logic.
- Vẫn cần đóng BootROM/remap/reset vector, secure warm entry, cache/SCU/L2/GIC và OP-TEE per-core trước khi chuyển Linux sang PSCI CPU_ON.

### SDRAM M1

- P1X sửa policy secure attribute thành raw `1`, reject raw non-secure `0` và shared `2/3`. Test có mô hình 10 port, 2 transaction IDs và boundary end-exclusive.
- P2D sửa encode/decode cleared rule. P2E thêm snapshot audit; indirect rule read **có thao tác ghi selector**, nên không xem là thao tác MMIO thuần đọc.
- P2F nhận disabled rule encoding `0x00FFF000` của U-Boot ngoài `0x00000000`.
- P2G/P2H kiểm tra đủ 20 slot, phát hiện stale allow-all và security corruption trên mock/source tests.
- Chưa có bằng chứng controller priority/master attributes và negative-access NS CPU/DMA trên board; firewall vẫn OPEN.

### SiP, debug opcode và boot status

- P1Q bỏ debug opcode `0x00F1D3C4`.
- P2J giữ ABI 2.0, đưa cờ SPL SHA-256 về zero khi chưa có verified evidence và chặn `C5_HWUID_HOST_ENABLE` trong firmware production.
- `GET_HWUID` và `LOCK_REGION` vẫn trả unsupported khi backend chưa được xác nhận. UID mock chỉ phục vụ host tests.

### PowerShell/YMODEM

P1S FIX1 ghi nhận `$PSScriptRoot` rỗng lúc bind giá trị mặc định của tham số `-Probe`. Cách sửa là resolve đường dẫn sau `param`, dựa trên `$PSCommandPath`/`$MyInvocation.MyCommand.Path`. Gói fix tự ghi giới hạn: mới static/asset tests; không dùng riêng README này để kết luận sender COM đã được kiểm thử. Capture query SMC là bằng chứng riêng cho probe.

### OP-TEE/GIC và entropy

- OP-TEE `boot.c` thực tế gọi `main_init_gic()` / `main_secondary_init_gic()`; port cũ dùng tên `boot_primary_init_intc()` / `boot_secondary_init_intc()`. GIC fix đổi đúng callback.
- Mode production giữ TF-A SP_MIN làm GIC owner để OP-TEE không khởi tạo Distributor lần hai; cấu hình double owner bị compile reject trong host tests.
- Report áp dụng xác minh 4 file TF-A và 2 file platform OP-TEE trước patch. Chỉ `main.c` và `conf.mk` của OP-TEE được sửa ở bước này.
- Generated config candidate: `CFG_WITH_ARM_TRUSTED_FW=y`, `CFG_TEE_CORE_NB_CORE=2`, `CFG_WITH_SOFTWARE_PRNG=y`, `CFG_CORE_ASLR=y`, `CFG_DT=n`.
- Audit vẫn ghi RNG seed zero / thiếu ASLR seed và chưa chứng minh entropy tin cậy. GIC fix không đóng các mục này.

## 8. Các mục phải đóng tiếp

1. **CPU1/PSCI:** reset ownership, vector/remap và secure warmboot, cache/coherency, GIC và OP-TEE per-core; test CPU_ON trên board.
2. **SDRAM isolation:** snapshot đủ 20 rule, priority/overlap, port/master attributes, programmer/readback được xác nhận; negative tests NS CPU và DMA.
3. **GET_HWUID / LOCK_REGION:** hardware backend thật; giữ unsupported tới khi đủ bằng chứng.
4. **Authenticated boot:** trust anchor và signature verification, kể cả test ảnh sửa/sai chữ ký bị từ chối.
5. **Entropy/OP-TEE:** xác định nguồn entropy và ASLR seed; khớp hash payload deployed với source/config/artifact.
6. **Nghiệm thu còn thiếu:** 4 SiP QEMU tests, PMF enable/runtime, cold-boot/reset reliability, rollback boot và chấp thuận sai khác spec ARMv8 BL31/EL3/SMC64 so với Cortex-A9 ARMv7 SP_MIN/SMC32; review TF-A v2.9 trong spec so với v2.13 được audit ghi nhận.
7. Sau khi thống nhất source/config và hợp đồng hardware, thực hiện **một lần build tích hợp**, xử lý lỗi cụ thể nếu phát sinh rồi board regression. Đóng TF-A theo yêu cầu trước khi mở rộng sửa OP-TEE.
