## 3. Các lỗi, sửa đổi và giới hạn quan trọng

### Entry TF-A và kết quả build

[Stage17 entry gate](../../../evidence/2026-10-23/output/STAGE17_20261023_012852/TFA_ENTRY_GATE.json) chỉ rõ mismatch, dù host tests và build bốn tầng PASS. [Stage18 contract](../../../evidence/2026-10-23/output/STAGE18_20261023_014600_3652/TFA_ELF_FLAT_CONTRACT.json) sau đó xác nhận entry `0x3e004920`, raw base `0x3e000000`, ELF/flat bytes khớp; `runtime_handoff_proven=false`, `authenticated_boot_proven=false`. Vì vậy không dùng PASS compile hoặc kiểm tra ELF để nghiệm thu boot.

TF-A trong các lượt one-pass vẫn `PASS_REUSED_STAGE7_SAME_PLATFORM_SOURCE`; TA ghi `PASS_ARM32_COMPILE_DEV_SIGN_ONLY`. Năm manifest source one-pass trong bộ này gồm 57 file mỗi checkpoint, tổng **285/285 hash khớp**. Đây là năm snapshot lịch sử, không phải 285 file duy nhất hoặc full upstream trees.

### Signed-FIT audit và firmware authentication

[Stage19 readiness](../../../evidence/2026-10-23/output/STAGE19_20261023_020011_6981/SIGNED_FIT_READINESS.json) ghi `CONFIG_FIT=y`, nhưng `CONFIG_FIT_SIGNATURE=n`, `CONFIG_RSA=n`, `CONFIG_SPL_FIT=n`, `CONFIG_SPL_LOAD_FIT=n`; required control key và kernel/DTB runtime đều chưa được chứng minh. Nhãn `STAGE19_SIGNED_FIT_AUDIT=PASS` nghĩa là audit chạy thành công, không phải signed FIT đã hoạt động.

Raw firmware slots vẫn chưa có signature verification/trust anchor được nghiệm thu. Stage26 report xác định authentication là `NONE_WRITABLE_SD_SHA_ONLY`. Hash manifest do cùng bên ghi SD cung cấp chỉ là self-check; không được đổi nhãn thành authenticated boot.

### Stage24 → Stage26: container, SFP và manifest

- Stage24 bổ sung contract cho OP-TEE v1 packed ARM32 header và code chuẩn bị init; `OPTEE_EXECUTION=NOT_ENABLED`. [Stage24 report](../../../evidence/2026-10-23/output/STAGE24_9phsvyve/REPORT.json) có cả source hash trước patch và `patch.new_sha256`; phải dùng đúng trường theo checkpoint.
- Stage24 SFP dài **62.368 byte**. Gate 64 KiB của lượt đó chưa đủ theo giới hạn **60 KiB = 61.440 byte** mà runner Stage26 áp dụng. Không ghi Stage24 BootROM-ready chỉ dựa vào gate cũ.
- Stage25 dừng vì giả định chỉ có một SFP hợp lệ; Stage26 xử lý bốn cửa sổ 64 KiB, chép cùng SFP mới vào cả bốn để loại fallback cũ. Đây là sửa tool/layout, không phải kết quả board.
- Stage26 sửa manifest U-Boot về đúng D53: hash/size bao gồm **toàn bộ `u-boot.img` và header 64 byte**, load `0x01000000`, entry `0x01000040`. Không dùng biến thể Stage25 hash riêng payload.
- Stage26 build source riêng, giảm verbose UART; [BUILD_PROOF](../../../evidence/2026-10-23/P32_source_review/P32_review_source/evidence/stage26_proof/BUILD_PROOF.json) ghi loader mới và SFP **61.424 byte**, thấp hơn gate 61.440 byte đúng **16 byte**. Đạt size/format không chứng minh BootROM đã chạy.

Nguồn: [Stage26 README](../../../evidence/2026-10-23/SECUREBOOT_STAGE26_MULTI_SFP_TESTSD/README.md), [report](../../../evidence/2026-10-23/output/STAGE26_20261023_033446_A3lfG2/result/REPORT.json).

### P29–P33: chọn source và chính sách key

P29 bỏ sót TF-A do matcher; P30/P31 bổ sung candidates. P31 chỉ so sánh mẫu: TF-A 75 shared file có 0 khác biệt; OP-TEE 62 shared có 50 khác biệt; U-Boot 116 shared có 3 khác biệt. Trong candidate hiện tại, implementation driver FPGA IMGPROC/7 IOCTL/DMA/IRQ/vb2 vẫn chưa được thiết lập. Bộ thu thập đã đối chiếu **819/819 file theo manifest gốc P32**. [P32 report](../../../evidence/2026-10-23/P32_source_review/P32_report.json).

Chưa có log devkit build/target runtime của patch P33 trong bộ thu thập; README mô tả host mock tests, bộ này không chạy lại chúng.

Header ABI v2 P33 phân biệt project unsupported status `1` với SMCCC unknown FID `0xffffffff`. Đây là source mới chưa tự động tích hợp; phải đối chiếu caller thực trước khi thay ABI. ## 6. Chín blocker cuối chuỗi P33

Theo [P33_readiness.json](../../../evidence/2026-10-23/P33_readiness.json):

| Blocker | Điều kiện còn thiếu |
|---|---|
| `tfa_lock` | LOCK_REGION có hardware enforcement và hostile-master tests |
| `tfa_uid` | Backend device UID được thẩm định; JTAG ID không thay HUK |
| `tfa_ddr_policy` | M1 SDRAM policy mặc định chưa enforce; cần transition an toàn và negative tests |
| `optee_entropy` | Software PRNG đang enable; chưa qualified entropy backend |
| `ta_secure_storage` | Persistent key/counter implementation được kiểm chứng |
| `spl_authenticated_boot` | Trust anchor và signature verification thật, kèm negative tests |
| `spl_handoff` | Exact provenance/config và runtime handoff của diagnostic source |
| `kernel_imgproc_driver` | Source thực cho 7 IOCTL, DMA-engine, IRQ, vb2 và OP-TEE client |
| `unified_build` | Một source manifest/build output thống nhất và kiểm thử SD/board tương ứng |

Bốn mục khác vẫn `REVIEW`: TF-A SMC32, OP-TEE monitor ownership, TA key policy, kernel OP-TEE config/probe. Các kiểm thử PSCI/CPU1, M1 CPU/DMA denial, SiP, secure storage/rollback và boot tích hợp vẫn cần evidence runtime riêng; không suy ra đã PASS từ các gate source.
